Research snapshot · 17 October 2026

When an answer becomes an interface.

Generative UI lets an AI choose how you interact with an answer—a chart to compare, a map to explore, or a form to clarify—rather than only choosing the next words.

Plain-language explanationsInteractive diagrams54 source snapshots

The core principle

The model proposes the experience. Your application controls what can render, which facts are shown, and what actions are allowed.

User intent“Which wells were down longest, and why?”
Grounded resultTools retrieve records, apply rules and calculate.
UI descriptionThe agent selects a widget, composes a layout or writes code.
Useful interactionCompare, drill down, filter or correct a fact.

What makes it generative?

The presentation is chosen and parameterized for the question. Reusable, developer-written charts can still produce generative answers. New source code on every turn is optional.

What stays engineered?

Components, data access, permissions, calculations, evidence, persistence and recovery. A valid UI description is only the start of a correct experience.

Our starting hypothesis: let the model compose the explanation; let domain tools compute the facts; let trusted components present them. This is a recommendation for our copilot, not a universal ranking.

Adjacent ideas: a coding assistant builds an app; a computer-use agent operates an existing app. Generative UI creates the interaction inside the current task.

Explore the spectrum

Move from words to widgets to composed interfaces to generated code. More freedom increases what the model can express—and what the application must validate.

Where does MCP Apps fit?

On a separate axis: where an interface runs and how it talks to its host. An MCP App can contain a prebuilt widget, a declarative renderer or a custom experience. Hosting is not the next rung of generation.

A spectrum, not a maturity ladder. Use the least complexity that supports the task. A short text answer can be better than an unnecessary generated interface.

The protocol map

These names overlap in conversation. Their responsibilities differ. Add a layer when it solves a real integration boundary.

A2UI

What should the interface look like?
Streaming declarations of components, data and actions.

UI description

AG-UI

1. Create a surface

A surface is one managed UI region. Choose its ID and agreed catalog before sending components and data.

Agent → client

{"version":"v0.9.1",
 "createSurface":{
   "surfaceId":"well-view",
   "catalogId":"your-approved-catalog"
 }}

Step 1 of 7. Choose Next to explore.

  1. Create: createSurface chooses a surface and catalog.
  2. Compose: updateComponents adds components with stable IDs and child references.
  3. Populate: updateDataModel supplies values for bound paths.
  4. Edit: inputs change local state; typing does not automatically write to the server.
  5. Submit: an action sends chosen values; backend validation is required.
  6. Refresh: recompute the result and its evidence after a validated change.
  7. Remove: deleteSurface removes the temporary region.

Surface = a UI region

A result panel can update independently. Its presentation state is not a database record.

Catalog = an allowed vocabulary

Register schemas, components and functions that match your design system. A custom WellMap needs an implementation on each target.P05

Structure and data are separate

Stable component IDs form a flat graph; bound paths supply values. Data can change without rebuilding the whole interface.P02

Local functions ≠ server events

Controls can react immediately; events send context to the agent. UI validation never replaces backend integrity checks.P07

Important gotchas before adopting A2UI
  • Pin the combination: protocol + renderer + catalog + prompts. v0.8/v0.9-family message shapes differ; userAction became action.
  • Path replacement: replacing a parent can remove sibling values. Preserve unsubmitted drafts separately.
  • Optional full-model sync: sendDataModel can attach surface state to outgoing messages. Keep private history and unnecessary raw data out of it.
  • Transport neutrality ≠ finished bindings: the guide lists A2A/AG-UI stable, REST planned and WebSockets/SSE proposed. Custom JSON delivery is feasible; examples remain incomplete.P06
  • Candidate discrepancy: the homepage mentions actionResponse and surfaceProperties; the detailed candidate omits them and describes typed bidirectional function calls (including callRendererFunction and callAgentFunction) and single-message instantiation. Check the exact schema/source. Inherited date metadata is not a reliable release chronology.P03
  • Adapter caveat: inspected CopilotKit examples use v0.9-era messages. Exact v0.9.1 adapter/package compatibility was not tested.

Interaction and hosting

A useful visual needs progress, tool results, user actions, errors and a place to run.

AG-UI

The live interaction channel

Streams run lifecycle, messages and tool events. Snapshots give the full state; RFC 6902 JSON Patch deltas update what changed.P12

Start runIdentify request
Stream workText, tools, state
Finish / errorSettle outcome

Fits: supported agent adapters, shared app state or backend interchangeability.

What you must still engineer

Run/thread identity, cancellation, late events, reconnect, ordered patches, retry idempotency and concurrent edits. Shared state is not durable memory or automatic multi-user consistency. Feature subsets vary; draft events are not compatibility guarantees.

MCP Apps

An app inside the assistant

A tool points to an HTML resource. The host displays it in a sandbox and mediates JSON-RPC over postMessage.P13

Tool callLinks UI resource
Host + viewInitialize sandbox
InteractTools and updates

Fits: delivering tools into existing compatible assistant hosts.

Lifecycle, permissions and fallback

Discovery → initialization → input/result delivery → interaction → teardown. Tool metadata links a ui:// resource with MIME type text/html;profile=mcp-app. Host CSP and tool visibility restrict capabilities; unsupported hosts receive the standard tool fallback. Test display modes, permissions and external map/font/script dependencies.P14

They can nest: put an A2UI renderer inside an MCP App, or an MCP App inside an A2UI surface. Documented patterns do not establish universal host/renderer parity.P09P10

Choose tools by their job

Protocols describe boundaries. Libraries and services give you implementations. Several can belong in the same stack.

Older comparisons miss two changes. Tambo Cloud announces closure on 31 October 2026: signups closed, hosted data deletion on 30 November. Thesys archives C1 documentation and directs new projects to OpenUI; this does not establish that C1’s endpoint has shut down.F12F15

8 tooling options. Roles overlap.

Vercel AI SDK UI

Baseline

Render typed tool results as your own React components. A foundation for known cards, charts and tables.

Mechanism
streamText + useChat + typed message parts.
Ownership
Open-source toolkit; direct providers are separate from Vercel Gateway.
Caveat
RSC remains experimental; official guidance favors AI SDK UI for production.
Version and RSC details

Inspected guide identifies v7 docs. RSC guidance lists abort limitations, remount flicker, suspense crashes, quadratic transfer and closed-stream updates. Not reproduced here.F01F02F03

json-render

Composition

The model writes a spec from your catalog; a registry maps it to actual components. Your code owns actions.

Mechanism
Flat React element map, JSONL patches, separate runtime state.
Ownership
Apache-2.0; Vercel Labs. Multiple targets, with potentially different maturity.
Caveat
Validate partial patches, references and persisted-spec migrations.
Streaming and action control

useUIStream handles stream state and abort; new sends cancel earlier requests. AI SDK helpers extract specs. Visibility/validation/action providers remain application-owned. Naming an allowed action does not authorize a backend change.F04F05F06F08F09

CopilotKit

Agent + UI

Connects agent backends, application state and UI. A2UI supports fixed or dynamically generated schemas.

Mechanism
Agent interaction layer, renderers and framework integrations.
Ownership
MIT repository; separate open components from optional services.
Caveat
Dynamic A2UI waits for the schema before streaming complete data items.
Why progressive rendering can still wait

A secondary model can generate schema/data. Middleware waits for schema completion before creating the surface. Check backend adapter, renderer, catalog, recovery and wire version together; inspected examples use v0.9.F10F11F13F14

assistant-ui

Conversation UI

A controllable chat surface with custom tool widgets, newer composition APIs and generated-frame options.

Mechanism
Tool UI, present vocabulary, generative UI parts and graph messages.
Ownership
MIT; optional Assistant Cloud for managed persistence/analytics.
Caveat
New composition subpackages do not inherit the shell’s maturity automatically.
Composition versus generated frames

Docs list 35 default present components and custom Zod libraries; its tree differs from generic UI parts. A2UI/channel conversions do not prove lossless parity. Generative Frame adds streamed widgets, patch specs and repair/screenshots, with distinct isolation needs. A composition example used ^0.0.4.F07F22F23F24

Tambo

Cloud closing

Registers React components the agent can generate or manipulate. Useful ideas for persistent, agent-visible controls.

Mechanism
Streamed props, existing “interactable” components and shared component state.
Ownership
MIT and self-hostable; self-hosters inherit maintenance responsibility.
Caveat
Do not start a new dependency on the closing Cloud API.
The reusable idea

Ordinary React state is invisible to the agent. Tambo’s component-state hook exposes values to follow-ups and rehydrates history. The pattern remains useful regardless of vendor lifecycle; a shutdown does not prove the approach obsolete.F17F19F20

Thesys OpenUI

Reactive UI

The model generates OpenUI Lang; a runtime executes registered queries, mutations and reactive controls.

Mechanism
Generation is separate from execution; local interactions can avoid another model call.
Ownership
MIT runtime; optional Gateway, Autofix and monitoring services.
Caveat
A constrained executable language differs from a JSON-only component tree.
State, actions and reliability

Local actions include @Run, @Set, @Reset; callbacks continue the conversation. Initial-state/state-update APIs support persistence. Gateway adds correction/fallback. Vendor token/ranking claims need testing; unknown components, invalid props, references and truncation remain possible.F18F25F26F27

Thesys C1

Archived docs

A hosted generative UI API with React rendering. Existing integrations should use legacy documentation deliberately.

Mechanism
API-generated UI; index lists streaming, actions, state and custom components.
Ownership
Hosted dependency: inspect current terms and migration guidance.
Caveat
New projects go to OpenUI. Legacy detail pages were inaccessible in the research browser.
Evidence boundary

Legacy feature claims were observed in the documentation index, not verified API contracts. Archived docs do not establish endpoint closure.F15F16

LangGraph UI

Graph-owned UI

Ship developer-written React bundles with graph deployments. Nodes emit named UI messages and generated props.

Mechanism
push_ui_message, stable IDs, updates/deletes and external component loading.
Ownership
Fits graph/Agent Server deployments; review surrounding platform terms separately.
Caveat
Graph-served bundles differ from a frontend-owned component registry.
When it fits

Choose it when UI belongs to graph deployments. Confirm bundle loading, persistence and self-host entitlements. The guide does not establish arbitrary safe code generation.F21

Evaluate AI SDK UI and/or assistant-ui around trusted visual components. Add composition when the task needs more flexibility.

State, trust and evidence

The hard part is keeping the interface aligned with reality while the user and agent both change things.

UI state

Selected filters, open panels and unsent form edits.

Owner: the client.
Rule: preserve drafts and focus across updates.

Conversation state

This user’s questions, references and task context.

Owner: user-scoped history.
Rule: another user’s conversation stays private.

Domain state

Inspections, rules, shared notes and formal corrections.

Owner: backend records.
Rule: validate, append provenance and recompute.

Try it: a draft is not a saved correction

An isolated teaching simulation. No well data is read or changed.

Draft: 5.4 bbl, not saved.

Authoritative value: 4.5 bbl.

Original remains visible. Simulated revision 1.

A catalog limits capabilities.

It bounds components and actions the model can name. Still validate props, URLs, result IDs, actor and scope. Declarative output can mislead even without arbitrary code execution.

A citation must lead somewhere.

Carry source references from calculated results into every visual. Show units, time bounds, applied rules and conflicts. A polished chart is not proof its numbers are correct.

Corrections, replay and large datasets
  • Formal corrections: retain original, author, reason and well/type scope; recompute affected results and mark earlier answers superseded.
  • Contradictory ordinary notes: show both claims. A note does not silently replace an inspection.
  • Replay: persist versioned results/specs, not mounted React instances. Retain compatible catalogs or disclose unsupported formats.
  • Result reuse: “show that as a table” preserves result identity and evidence instead of silently changing the query.
  • Large data: use scoped result handles and pagination instead of repeatedly routing all rows through the model.
  • User switch: clear or refetch scoped state. A frontend picker is not backend authorization.

What research actually demonstrates

Preference, protocol validity, visual conformance and task success measure different things. Their scores cannot be combined into one “best generative UI” ranking.

Full-page generation + PAGEN

Complete pages, tools and postprocessing show expressive range. The preference comparison explicitly ignores generation speed.

Designer feedback + conformance

A study with 12 UI/UX practitioners examines designer-aligned generation.

Prompt optimization and conformance scoring shape outputs. Short, constrained sessions and screenshot-based scoring limit conclusions.

GenUI-Harness

Tool grounding + generated interactions

Reports a 4.48 percentage-point Pass@3 gain on UI-TAU Lite over its baseline.

Pairs a tool agent with a UI coder. The simulator can inspect source/reference goals; the survey selects consistently usable interfaces.

Lesson: test real record selection and final backend state with source-blind users too.R06Full text

One result, several views

Keep result ID, query/time bounds, revision, units, source references, applied rules and conflicts together. A table and chart should express the same answer.

Domain rules stay in tools

Derive production from the type manual; count seven days per non-producing inspection; apply formal false-detection corrections. Repair duration is not the downtime metric.

Suggested path: typed components first; compare a declarative alternative on the same vertical slice. Add AG-UI for a real agent integration need, A2UI for a useful shared UI contract, and MCP Apps for assistant-host distribution. Generated code comes later if a real expressive gap remains.

Research proposals, not adopted architecture decisions. Honor explicit visual requests, provide accessible alternatives and retain evidence if a requested visual is unsupported. Demonstration values in this guide are illustrative.

What to test before choosing

Use the same model, prompts, backend results and scenarios across candidates. A nice demo is not enough.

  • Coverage & explicit choiceAll six visuals; “show it as a table” preserves the result and citations. Include a multi-widget compliance answer.
  • Corrections & scopeQ12 → Q2; Q13 spill recomputation; Q14 type rules; Q15 shared updates, with original evidence intact.
  • Privacy & conflictsQ11/Q16 private recall; Q17/Q18 show both claims with attribution.
  • Stream resilienceTruncated JSON, reconnect, cancellation, late events, malformed props and repeated submissions.
  • Drafts & replayRefresh without losing input/focus; persist results across catalog and data revisions.
  • Grounding & empty statesMissing coordinates, empty periods, unseen data and invalid source IDs produce honest fallbacks.
  • Accessibility & actionsKeyboard, focus, screen readers, non-color meaning and one correct backend mutation.
  • Cost & useful latencyFirst useful result, final completion, model calls, tokens and repair rate. Use adequate samples for p50/p95.

Reject a candidate if it loses correction drafts, cannot isolate users, loses evidence or cannot render/replay required results. Extra flexibility must justify dependencies and engineering effort.

Sources, confidence and open questions

Documented capability is different from measured reliability.

Observed

Protocol roles, documented version/renderer status, lifecycle announcements and published APIs. Bounded by the research date.

Recommended

Trusted domain components, evidence-bearing results, separate state scopes and a two-candidate vertical slice. Still needs project validation.

Unverified

Fastest/cheapest stack, model/catalog fitness, cross-renderer parity, production support, hosted economics and end-to-end accuracy gains.
