# Google and ChatGPT: product patterns for an operator workspace

Researched 2026-10-17. Primary first-party sources only. This is input to a fresh React prototype, not a recommendation to embed either vendor's product or reproduce its styling. Availability below is limited to what each cited source actually states; announcements do not prove universal rollout. Living help/developer pages were checked on the research date.

## Main finding

The useful common pattern is a conversation that produces an **object the user can explore**, with a small initial presentation and room to focus when needed. The operator app should combine that pattern with its own stricter requirements: visible evidence, immutable historical results, deliberate Save, fresh read recipes, and explicit review of writes. Those operator requirements are product decisions, not claims about either vendor.

## Derivations for the fresh app

These are design recommendations inferred from the sources and the operator brief. They are not claims about vendor behavior.

1. **A calm start, a useful answer.** Start with one prominent composer and a few task examples phrased in operator language. After a request, show a short conclusion followed by one primary result object, rather than filling the page with every possible widget. This applies question-specific Google layouts and ChatGPT's compact-to-focus progression.
2. **One result, two useful scales.** Inline: title, answer, compact visualization, scope, source count, and an obvious Expand control. Focus: the same result identity, complete data and controls, evidence access, a close/back affordance, and continued conversation. Desktop can place chat beside focus; mobile should show one principal surface and preserve a clear route back. Avoid nested scroll cages in the answer stream.
3. **Purposeful components.** A production estimate gets a comparison/trend chart plus calculation assumptions; downtime gets a weekly inspection timeline; conflicting status gets a two-source comparison; a source excerpt gets its own reader. Rich output is chosen because it clarifies the question, never because a component is available.
4. **Selection is the bridge to follow-up.** Clicking a trend point selects its week/asset. Selecting a table row shows the record and source. The composer can display a removable context chip such as “Pump P-104 · week ending 12 Oct”. The user can then ask a scoped question without retyping identifiers.
5. **Critical evidence stays near the claim.** Always expose timestamp, period, units, and provenance entry point. Focus can add source excerpts, calculation inputs, conflicts, and missing records. A compact inline answer should still reveal that evidence is stale or contradictory; those conditions are not optional advanced details.
6. **History is stable.** Opening, expanding, selecting, or returning from focus does not change old result contents. A new parameterized read produces a new dated result. Keep the earlier result accessible, and clearly indicate which one is currently in focus. This applies the historical Canvas lesson without copying editable-document semantics to operational records.
7. **Save is a deliberate verb.** Only the explicit Save action creates a saved view. Distinguish private conversation history from a personal saved recipe and from shared knowledge. A saved recipe retains question intent, asset scope, display choice, and configurable dates/filters; opening it should offer/run a fresh read and display the new result time. Never equate a selected card or expanded panel with Save.
8. **Controls disclose effects.** “Change period”, “Compare assets”, “Show records”, and “Open source” describe read/navigation effects. “Save view” describes personal persistence. “Propose correction” leads to an explicit review showing old value, proposed value, justification, affected record, and confirmation. Preserve raw source evidence when corrections are recorded.
9. **Light visual system, consistent landmarks.** Use restrained light surfaces, clear typography, and color tied to information. Keep result title and scope in the focus header; show a return-to-conversation action. Do not interpret “generative” as permission to rearrange navigation, action placement, or safety states on each turn.
10. **Implement the useful capability floor first.** The fresh prototype should demonstrate a small summary, at least two different result forms, inline-to-focus, selection-to-follow-up, source inspection, and explicit saved recipe reopening with editable parameters. Optional later forms include map, document reader, or workflow review. A library/protocol choice alone does not demonstrate the intended UX.

## Component and behavior floor

| Primitive | Initial presentation | Deeper exploration | Effect |
| --- | --- | --- | --- |
| Insight | Short answer, figure, scope | Supporting records and assumptions | Read |
| Trend | Legible chart with units and period | Select points, alter period, compare series | Fresh read or local view change, visibly distinguished |
| Comparison | Small ranked table or chart | Sort/filter/select asset; inspect the corresponding evidence | Read |
| Evidence | Source count and meaningful citation label | Excerpt, original value, timestamp, source locator | Read |
| Saved view | Explicit Save action | Named recipe, parameters, last run time, Run again | Personal persistence followed by a new read |
| Correction | Proposed change summary | Before/after, reason, record, explicit commit control | Shared write only after explicit user action |

## Boundaries

- Neither the cited Google product articles nor OpenAI developer UI guidance establish that ChatGPT uses A2UI. Google Research's described generated-code path is also different from assuming a fixed declarative component protocol.
- ChatGPT developer UI guidance documents host integration patterns. A standalone React app can adopt the interaction principles without adopting MCP, an iframe host, or the Apps SDK UI package.
- Google launch visuals and interface-generation research do not verify reliability for oil-field calculations or evidence retrieval. The operator app needs deterministic calculation contracts and source-backed results regardless of presentation.
- Product docs change. Native ChatGPT Canvas is treated as historical precedent here because its launch article explicitly directs readers elsewhere for current capabilities. The current Voice page supersedes assumptions drawn from older Voice FAQ snippets.
- The prototype may demonstrate these patterns with labeled synthetic data. It must not imply that a polished component proves live ingestion, production authentication, persistent backend memory, or operational write execution.
